# Changelog

## Unreleased

- `consent.requests(log_text)` reads the unified log's consent requests: which program asked (`asker`, an executable path or a bundle id) to control which app (`target`), and the answer logged after it (`result`, None while a prompt still waits). The log names both while the screen is locked, when a prompt's words cannot be read. `recent_requests(minutes)` runs `/usr/bin/log` for them, `waiting` keeps the ones still unanswered, and `short` gives a program's short name
- `consent.timed_out()` reads, from the user's consent database and only reading it, the Apple Events consents macOS denied because nobody answered the prompt in time. Until a new prompt is answered, that program's every Apple Event to that app fails with -1743 and no message. None when the database cannot be read (it needs Full Disk Access)
- `consent` lists an app's request to control the computer through accessibility features (universalAccessAuthWarn, "Open System Settings" and "Deny") with `kind` "settings": only the person can grant it, in System Settings, so `answer("allow")` refuses it and presses nothing, while a deny presses "Deny" by its title. Every other prompt has `kind` "press"
- `consent.prompts()` also lists prompts on other desktops, after the ones on screen, marked `on_screen: false`. A prompt on a desktop nobody is looking at waits as long as one in front of them, and it was missing from the listing
- `consent.read_words(pid, wid)` reads a consent prompt's words from its text through the Accessibility API, with the quotes straightened. It reads a locked or covered screen, where a picture of the prompt cannot be taken, and needs the Accessibility grant
- `consent.answer(..., by_title=True)` presses any owner's prompt by its button's title (`press_button`), and a press that leaves the prompt open is tried once more (`tries`). Without `by_title` a "wants access to control" prompt is still answered with the keyboard
- The station's `consent` input presses every owner's prompt by title with its own Accessibility grant, where it used to refuse the "wants access to control" prompts, and `{"type": "consent", "choice": "read"}` answers the front prompt's words and its two buttons without pressing anything. `consent.ask_station` takes "read" too
- `brave.run`'s `timeout` (`--timeout` for `claude-human brave`) holds for the whole run, opening the window included. Every AppleScript and yabai call during the run is cut to the time left, the page and the script share the one deadline, and closing the run's own window afterwards may take `CLOSE_GRACE` (5 s) more. A browser that answers nothing used to keep the run going for minutes, since each call waited out its own 30 s. The timeout's message says how long it waited, and a prompt seen then is named ("a macOS prompt is blocking Brave")
- `claude-human steps --open NAME` opens the app by its bundle's name when that differs from the name its windows carry (`--app`). `--open` alone still uses the `--app` name, which `open -a` refused for such an app
- `brave.run` and `claude-human brave` fail at once with `blocked_by UserNotificationCenter` (`brave.Blocked`, exit 1) when a macOS consent prompt is on screen, before a window is opened, and in either wait when the prompt appears during the run. Behind such a prompt every AppleScript call waits out its own timeout, so a run given `--timeout 90` went on for minutes. `brave.blocked_by()` names the prompt's owner. `brave.new_window` now waits `wait` seconds by the clock rather than a count of listings that could each take 30 s
- `claude-human consent list --out PNG` exits 1 and says why on stderr (and as `image_error` in the listing) when no picture was saved, for example when the process may not record the screen. It used to exit 0 with no file. `consent.capture_why` gives the reason, and `consent.capture` keeps its yes or no answer
- `brave.start()` opens a browser that is not running with its last session and waits until it answers, for a browser that something else ended. A running browser is left as it is ("skipped"), so nothing is stopped.
- `station.steps` and `claude-human steps OUTDIR (--window ID | --app NAME)`: drive one window through a running station a step at a time. Steps arrive as files (`cmd-<n>.json`: click, double, key, text, scroll, page, raise, wait, noop, stop) and each result is written to `done-<n>.json` with the station's answers, a picture and its text lines. The session waits for an unlocked session, keeps the display awake for its whole time, opens the app when asked, brings the window forward before each input, pages until the picture stops changing, and on every way out (a stop step, no step in time, its time cap, a signal) stops keeping the display awake and runs its exit hook (`--relock` locks the session again). `station.client.windows` lists the windows the station can show
- The station's `scroll` takes `"unit": "line"` (a mouse wheel's line steps) and `"phased": true` (pixel deltas wrapped in the began, changed and ended phases a trackpad sends). Some apps, Qt apps among them, ignore plain pixel scroll events, which the station still sends by default
- The station takes `{"type": "raise"}`: the named window is brought to the front through yabai, which also switches to its desktop, and the answer says whether it came. A window left on another desktop answers no click and gives no picture
- `sckshot` leaves the window's shadow out of a one-window capture (`ignoreShadowsSingleWindow`, macOS 14 and later). With the shadow, window and shadow were scaled into the window's size, so the window filled about 95% of the picture with blank margins and a point read from the picture was off by that much. A helper built before this keeps the old picture until it is built again
- The station's `/shot?full=1` (and `station.client.shot(window, full=True)`) returns a window at its own size and a high JPEG quality. The ordinary shot is made small for streaming to a phone, which is too coarse to read small text or digits from with OCR
- `ocr.lines(path)` reads the text lines in a picture with macOS's Vision framework, each with its box as fractions of the picture from the top left, in reading order. `find` picks a line by its exact words and side of the picture, `in_band` the lines in a horizontal band, and `middle` the point to press. Reading needs no permission
- `station.client`: a client for a running station, for a program without Screen Recording or Accessibility of its own. `shot(window)` returns a JPEG of one window and its size, and `click`, `scroll`, `key` and `text` send the inputs the station takes, each returning the station's answer, its refusal (screen locked, a dialog up, the point covered) or why it could not be asked
- The station's click check (`screenshot.covered_at`) no longer counts a window above the ordinary layer that spans the whole display. Notification Center keeps an opaque full-screen window on layer 21 that a click passes through wherever it draws nothing, and every click on an ordinary window was refused as covered by it. `covered_at` takes the display's size, `on_top_at` passes the main display's, and a banner or panel smaller than the display still counts
- `@drkostas/expo-ntfy` 0.5.1: the notification relay sends a long message's whole text. Android keeps it in the notification's big text (`EXTRA_BIG_TEXT`), while the short text line (`EXTRA_TEXT`) may hold only what the collapsed notification shows, so the relay used to forward a cut-off preview. It now sends whichever of the two is longer
- `consent.ask_station(choice, token=, station=)` answers the front consent prompt through a running station (`{"type": "consent"}` on `/input`, a master token), so a process without the Accessibility grant, such as a launchd job, can still press Gatekeeper's "Open" or "Cancel". It returns the station's answer, or why the station could not be asked
- `consent` knows Gatekeeper's first-open prompt ('"X" is an app downloaded from the Internet. Are you sure you want to open it?'), owned by CoreServicesUIAgent, with its own buttons: `allow` presses "Open" and `deny` presses "Cancel". While it is up the app sits stopped with no window and `open -a` hangs, and ending the app leaves the prompt on screen. Its buttons are pressed by their titles through the Accessibility API (`consent.press_button`, `AXPress` in the window found by its window-server id), which needs the Accessibility grant, and the press is observed to close the prompt like a keyboard answer. `BUTTONS` names each owner's two titles, every listed prompt carries them as `allow` and `deny`, and `AX_OWNERS` names the owners pressed this way
- The station's `/input` takes `{"type": "consent", "choice": "allow" | "deny"}` from a master grant only (403 for a pinned one), through `StationAuth.perform` like `spotlight`. It answers the front consent prompt of an owner in `consent.AX_OWNERS` with the station's own Accessibility grant, and it is the one input not refused while a system dialog is up, since that dialog is what it answers. A prompt that takes the keyboard helper is refused with that reason
- `keys.front` and `claude-human key` find the front window when yabai has none to report (a system dialog, or a window yabai does not manage): the frontmost application's first on-screen window in the window server's list (`front_pid` from `lsappinfo`, `front_of`), marked `"source": "window server"`. `press` takes `windows=` for that list
- The station refuses a press (`down`, `click`, `dblclick`) in a named window unless that window is the topmost one at the point, as it already does for text and keys. The refusal carries `covered` and names the window on top as `on_top`. A window of the same application, an almost transparent one and system chrome do not count. A release or a drag after an accepted press is never refused. `screenshot.covered_at` is the pure check and `screenshot.on_top_at` reads the window list; a screen without `on_top_at` uses the package's
- `android.launch_how(serial, package, run, link=)` starts an app in turn by its launcher activity (`am start -n`), by the launcher intent limited to the package, and by a link the app opens (`link`, or the one `android.LINKS` names), also limited to the package, and says which way worked. Some phones name a launcher activity, an activity alias the app switches between, that `am start -n` then reports as missing, and `launch` returned False there. `am start` can exit 0 and still print an error, so `started` reads its output too. `launch` keeps its name and return type and takes `link=`. `checked_tap` and `android tap --link` start the app the same way and report the way as `launched`, and `claude-human android launch` does only that step
- `android.checked_read` and `claude-human android read`: an app's screen from the view tree, as nodes with their text, description, resource id, class, bounds and clickable, scrollable, focused and selected flags (`android.nodes`). It reads nothing on a locked phone or while another window has focus for all of `wait` seconds, and refuses when the focus or the lock changed while the tree was read, or the tree held only other apps' nodes, so a launch that failed quietly cannot hand back another app's screen. Nodes of other packages are left out and counted. It starts an app without focus as `checked_tap` does, or refuses with `start=False` (`--no-start`)
- `process.environment_of(pid, names)`: the values of named environment variables in another process's own environment, read from one `ps -Eww` (macOS has no /proc), picked out by name so a command argument holding an equals sign is not mistaken for one, the last value winning when a name repeats, and {} when the process cannot be read. A process started in a new session (detached) keeps the environment of the terminal that started it, so the pane or window it came from can still be told
- `brave.upload(window, selector, paths, done=)` and `claude-human brave upload WINDOW SELECTOR FILE...`: put one file or several into a page's `<input type=file>` as if the person had chosen them. Each file is sent in parts checked as they land and as a whole (CRC-32), the files are set on the input through a DataTransfer, and the input fires `input` and `change`. `done` is a value the page fills after its upload, waited for until it holds still for `settle` seconds. A file over `max_bytes` (25 MB), several files for an input without `multiple`, or a selector that names no file input is refused before anything is sent, and no file contents reach an error. `brave.js_in` and `brave.run` take scripts of any length the same way: a script over 4 MB is sent in checked parts (`brave.send`) and run with an indirect eval. `brave.osa` passes a script over 100 KB to `osascript` on standard input, since macOS holds a program's arguments to about 1 MB, which stopped scripts of about that size before. Every existing name and signature is unchanged
- `viber_desktop`: read Viber Desktop's local message database (`viber.db`, one per signed-in account under the app's data folder), read only. `snapshot(path)` copies it, with what its write-ahead log holds, into memory through a read-only connection, so the file and its log are never written and no chat is opened in the app (opening a chat in the app is what marks its messages seen). `chats` lists the conversations newest first with a title each (the group's name, or the other person's name or number), `find(title)` matches one exactly, and `messages(chat, limit, tz=)` gives the newest messages oldest first as rows with the sender, the whole text, the time and Viber's message type. A message whose text Viber keeps only in its JSON details (a business account's message, a link's preview, a file's caption) takes its text from there (`info_text`). Reactions and an edited message's earlier versions are left out. Viber's format is undocumented, so `missing(conn)` names any table or column the readers need that a file lacks, and the readers raise `SchemaChanged` rather than guess
- `android_browser.pinch(port, url, x, y, scale, speed=)`: a two-finger pinch in a phone browser's tab with the browser's own synthetic gesture (`Input.synthesizePinchGesture`), which on Android feeds touch events into the browser's view, so the page's touch handlers and the browser's own zoom both see two fingers. It works where the shell may not write to the touch screen
- `android_touch.checked_pinch` refuses at once, naming the reason and `android_browser.pinch`, on a phone whose security policy (SELinux) refuses the shell a write to the touch screen though the file's mode allows the `input` group. It opens the device for writing without writing anything before it moves a finger, where it used to report every gesture as one that did not finish
- `brave.close_tab` reads the tabs back up to `reads` times (4), `gap` seconds apart (0.5), before a tab still listed counts as a failure. The browser may list a tab it was just told to close for a moment, most often when it was the window's last one, and the single read-back reported a closed tab as a failure
- `retire.hold_app(..., root=True)` holds a path only root may move (a daemon's plist in /Library/LaunchDaemons, a privileged helper tool, an app that root owns) through `sudo -n /bin/mv`, and its undo moves it back the same way, recorded as `root` in the undo. The moved file keeps its owner. `hold_app` also holds any file or folder an app left, not only the app (a launch agent's plist, a support folder)
- `android_touch` and `claude-human android pinch`: a two-finger pinch on an Android phone over adb, written as the touch screen's own multi-touch events (protocol B, two slots) to the device `getevent -pl` lists with multi-touch positions and `INPUT_PROP_DIRECT`. `adb shell input` has one finger and cannot pinch. `checked_pinch` waits for `android.tap`'s checks (focus, no banner, no call, no input for `idle` seconds, a still screen around the point), refuses on a locked phone or a turned screen, and always lifts both fingers: the last frame lifts them, the script on the phone writes it again if stopped, and so does the caller when adb fails. `touchscreen`, `screen_size`, `rotation`, `event` and `pinch_frames` are pure
- `android_browser` and `claude-human android browser`: open an address in a Chromium browser on the phone (`am start`), and run a script in the tab that shows an address through the browser's debugging socket (`chrome_devtools_remote` or `<package>_devtools_remote`, forwarded with `adb forward tcp:0`), returning its value. The forward is refused when the socket belongs to another browser, and removed after. The websocket the protocol needs is a small client of the package's own, so it adds no dependency
- `tasks.by_hand` finds an instruction after a place set off by a comma ("In the app on your phone, open the page"), and the gestures (pinch, spread your fingers, swipe, scroll, drag, long-press) are in `HAND_VERBS`. A sentence where someone else acts after such a place still passes
- `android_files` and `claude-human android files` read the new files in a folder on an Android phone, only over adb and only reading. `newer(serial, since, folder)` lists the files changed after a time (hidden files and, by default, anything that is not an image left out), `settled` says whether a burst is done (its newest file `quiet` seconds old by the phone's clock, so one listing answers and no state is kept), `wait_new` lists until it is, `pull` copies the files to a local folder once each, and `contact_sheet` arranges them on one picture with their names (the `sheet` extra, Pillow). Nothing taps, moves or deletes anything on the phone
- `keys` and `claude-human key` press key combinations (such as `cmd+ctrl+left`) in one named window through a running station, which holds the Accessibility grant that posting a key needs. `press` waits until the Mac has had no keyboard, mouse or trackpad input for `idle` seconds, brings the window forward with yabai when another one is in front, presses each combination in turn, stops at the first one the station refuses (the station refuses a key for a window that is not in front), and puts the window that was in front back. `parse` turns a combination into its key code and modifier flags, and `idle_seconds` reads the HID idle time
- `whatsapp_web.CLOSE_CHAT` closes the open chat. It presses Escape, which closes the open chat in WhatsApp Web, and reloads the page when a chat still shows a second and a half later, since a page that has just loaded has none open. A chat left open after a read shows every message that arrives in it, and an open chat is how WhatsApp marks messages read, so a reader that opens a chat closes it again
- `whatsapp_web.STATE` reads a page that WhatsApp Web shows when another window of the same browser holds the session ("WhatsApp is open in another window. Click Use here") as `elsewhere`, and `USE_HERE` presses "Use here", which takes the session back to this window. WhatsApp Web runs in one window of a browser at a time and shows that page only while the browser is linked, so `elsewhere` means linked but busy elsewhere, not signed out
- The private-terms workflow runs on `${{ vars.RUNS_ON || 'ubuntu-latest' }}`. A repository that copies it and runs its jobs on a self-hosted runner sets the repository variable `RUNS_ON` to that runner's label, and the check runs there; with the variable unset nothing changes. A private repository whose hosted Actions minutes have run out can then still pass its own check
- `android.tap` and `claude-human android tap` wait, up to `wait` seconds, for more than focus before they tap, and refuse with the reason when one does not hold: no heads-up notification (SystemUI's pinned mode, a banner still leaving, or its touchable area, since a banner takes no focus and `mCurrentFocus` misses it), no call (the SIMs' call state or the audio mode, which also shows a call an app makes over the internet), no input for `idle` seconds (`dumpsys power`), and a still screen around the point (a band of rows hashed twice on the phone, so only the hash travels). After the tap they read the view tree back with `uiautomator dump` and report the focused window and the texts that appeared and went. `checked_tap` returns the whole report, `summary` one line, and `heads_up`, `in_call`, `idle_s` and `texts` read each source on their own. A tap is input too, so taps in a row are `idle` seconds apart
- `tasks.pictures`: pictures that go with a task or a question, for a person to look at on a phone. `store(path)` copies a picture into a folder named by its content (PNG, JPEG, GIF, WebP or HEIC, read from its first bytes, at most 25 MB), and on macOS shrinks it to 1600 pixels on its longer side with `sips` and turns HEIC into JPEG. `data_uri(id)` gives it back as a `data:` URI and reads only an id of its own form. `paths_in(text)` finds the pictures a text names by path. A path on the computer meant nothing to a person answering on a phone
- `whatsapp_web`: scripts that read WhatsApp Web from a tab a program controls, and parsers for their answers. `STATE` says whether the page shows the chat list, the QR code (and whether it has loaded), the phone-number form or a link code. `LINK_BY_NUMBER` and `fill_number_js(number)` take the page to its 8-character link code, which the person types into WhatsApp on their own phone. `CHATS`, `open_chat_js(title)` and `MESSAGES` read the chat list and the open chat's loaded messages, and `parse_messages` turns them into rows with WhatsApp's message id, the chat's id, who sent each one and its time from the line WhatsApp puts before it (`parse_prefix`, `day_first` for the browser's date order). Nothing in it sends a message or types a code. The signed-out page and the phone-number form were measured on the live page: the link works only once the QR has loaded, and the number must carry its + and country code, since the form reads a number without one as another country's

Only the listed packages are forwarded, each notification once, and what the endpoint does not take waits in a bounded file queue and is sent again with a backoff. `npm run compile:service` compiles it beside the ntfy service.

- `serving`: a local HTTP server that finishes the requests it is answering before it stops. `DrainingMixin` counts the requests in progress (from the moment each is accepted), and `serve_until_stopped(server, drain_s=10)` turns SIGTERM or Ctrl-C into a drain: the server stops accepting, the open requests get up to `drain_s` seconds, then it closes. Python's default SIGTERM ended the process at once and every request on a daemon thread died with it, so a planned restart broke the calls in flight. The station and the task server use it. `retry_refused(call)` repeats a call whose connection was refused (it never reached a server, so any method is safe) and never one that got in
- `focus`: Do Not Disturb while an agent drives a window, and the person's own Focus kept. macOS gives a script no focus command, so the one path is two Shortcuts `Set Focus` actions run by name through the `shortcuts` CLI; until they exist `begin` answers ok False with what to make, never a silent pass. Every change is observed from the Focus daemon's own assertion store, `begin` hands back what was running for `restore`, and a Focus the person had running is never cancelled
- `desktops`: Mission Control desktops and the windows on them, asked of yabai, for questions CGWindowList cannot answer (it sees only the visible desktop). Every command verifies its effect by asking again, because yabai exits 0 having done nothing more than once; labels, never indices, leave the module as identifiers, with a space's uuid as the identity that survives a renumbering and a yabai restart (`relabel`, `label_for`); an empty or truncated query answer raises as an unreadable machine (often a locked screen) instead of reading as an empty one
- `retire` retires a macOS app so that nothing starts it again, and undoes that retire step by step. Each step (`disable_service`, `unload_service`, `disable_extension`, `quit_processes`, `hold_app`) does one thing, reads it back and returns a JSON record with its undo. `retire()` runs them all, and one failed step never stops the rest. `undo()` brings the app back first and enables every service before it loads any, because launchd refuses to load a disabled service. A step that was already done before the retire is left as it was unless the caller says an earlier retire of its own did it. The app is renamed into a dated hold folder on the same disk, never copied and never deleted. Processes are quit by signal, never by AppleScript, and system domain commands run through `sudo -n`. Every command goes through a `Host`, so tests use a stand-in launchctl and process list
- `session_lock` keeps a password manager CLI to one session at a time across processes (Bitwarden's `bw` keeps one session per account, so a second `bw unlock` ends the first). `SessionLock` is an exclusive flock on a state file that names its holder (pid, act, program, since when), serves waiters in the order they came, refuses a second take in the same thread, and lets go when its process dies. `run()` refuses a call when the lock file was removed and names the running call in the lock, so the next holder ends a call that a killed holder left behind. `bw_session()` unlocks `bw` with the password through a pipe, sets `BW_NOINTERACTION`, and runs `bw lock` and releases the lock on every way out
- `process`: whether a process lives (`process_alive`, None when it cannot be told, True for another user's process), the process at the other end of a local TCP connection (`peer_pid`), a process's parents from a process table (`ancestors`), and a process's memory footprint in about a microsecond (`footprint_gb`, `total_gb`: phys_footprint from proc_pid_rusage, the figure `top` shows as memory, where `top` takes about 0.65 s)
- `brave` and `claude-human brave URL JS_FILE`: run JavaScript on a page in the person's own signed-in browser (Brave by default, any Chromium browser AppleScript can drive with `--app`), in a window of its own that is closed afterwards. `--keep-open` leaves the window for a step the person finishes and prints `WINDOW <id>` (and `YABAI <id>` when yabai is installed, taken when the window is made, so it can be moved at once). With a `--key` (by default the tmux session it runs in) a caller's next `--keep-open` run reuses its window while the browser has it, so a flow of several steps keeps one window. `brave.list_tabs` asks each window for its tab ids, addresses and titles in three calls: about a minute for a thousand tabs asked one by one, under a second this way
- `@drkostas/expo-ntfy` 0.4.0: `keyTagPrefix` names a notification by a tag (`key:<name>` with the prefix `key:`), so a later message with the same key replaces it in the tray instead of adding a second one. `clearTag` lets a sender take one back: a message carrying that tag and a key tag removes the notification of that key and shows nothing. A request that was answered, ran out or failed no longer leaves its notification behind, beside the newer ones about the same thing. Both are off by default.
- `station.prepare`: `activate` focuses the recipe's own window by its id through yabai when the caller names it (`Preparer.run(..., window=id)`, or `--window <id>` read with `argv_window`), and activates the app only otherwise or when yabai refuses. Activating the app raises its key window, which can be another window on another desktop: a browser asked to show a page it had just opened in a new window took the person to the desktop where they last used the browser, and the page was not there
- `@drkostas/expo-ntfy` 0.2.1: `pollTopicOnce` gives up after `timeoutMs` (default 20 seconds, `POLL_TIMEOUT_MS`). It aborts the fetch through an `AbortSignal` and also stops waiting for a fetch that ignores the signal, and it then rejects without announcing anything or moving the mark. Before, a topic that never answered kept the background task pending, and Android's WorkManager starts no other run of a task while one is pending, so one hung connection stopped every later background poll.
- `screenshot.activate` no longer brings Finder back with `open -b`. To a running app that is a reopen, and Finder answers a reopen with no window open by opening a new window at its default folder on the visible desktop, so giving focus back after another app took it (Finder is in front when the desktop itself has focus) made Finder windows appear. Such apps are listed in `screenshot.NO_REOPEN`, and `activate` returns False for them without asking
- CI compiles the Android service the expo-ntfy plugin writes (`npm run compile:service` in js/), against the Android 36 platform and the libraries the plugin adds, so a service that does not compile fails a pull request instead of an app's build.
- `screenshot.capture_approvals()` and `capture_approval_of()`: when macOS last asked each app to confirm that it may keep recording the screen, and when it asks again (macOS 15 and later ask monthly for an app that records without the system picker). Read only, from the system's own file, with the dates in UTC.
- The station's refusal while a system dialog is up carries the dialog's app as `blocker`, and `QuartzInput(blocked_detail=...)` may be a function of that name, so the text can say which question is waiting.
- `@drkostas/expo-ntfy` 0.2.0: a message's `view` actions become buttons on the notification, up to three, each opening its link in the app like a tap (and only a link that starts with `linkPrefix`). The priority picks one of three channels. At `alarmPriority` (default 5) the message plays the phone's alarm sound as an alarm and comes through Do Not Disturb where Android allows it. At `chimePriority` (default 4) it chimes on the channel messages were always posted on. Below that it makes no sound. A message published with ntfy's default priority (3) is now silent, so set `chimePriority: 3` to keep its sound. A notification folds to its title and the first line of the message, and pulls down to the whole message. `subTextTagPrefix` shows a tag's value next to the app's name. The manifest asks for `ACCESS_NOTIFICATION_POLICY`, so the person can give the app Do Not Disturb access.
- `@drkostas/expo-ntfy` 0.2.0 also carries the fix written down for 0.1.2, which was never published. Tapping a notification that carries a link now opens that link. The service built the tap from the app's launch intent with the link attached, and the launch intent carries `CATEGORY_LAUNCHER`, so when the app was already running Android only brought its task to the front and dropped the link: the tap opened the app on whatever screen it was last on. A link now opens as a `VIEW` intent aimed at the app's package (new task, single top), which a running app receives as a new intent. A notification without a link still opens the app. The service can also be started from outside without opening the app, with a `<package>.START_LISTENER` broadcast to the receiver (`adb shell am broadcast -n <package>/.BootReceiver -a <package>.START_LISTENER`), for a phone that did not restart it after an update.
- `screenshot.screen_locked()` and `unlock.is_locked()` return `None` when the lock state cannot be read. A process outside the login session (a launchd daemon, the system domain) gets no session dictionary, and both functions used to read that as unlocked while the screen was locked. A caller that only tests truthiness behaves as before. `is_locked` now uses the same reader as `screen_locked`.
- The two npm packages are released from GitHub Actions, `@drkostas/expo-ntfy` on an `expo-ntfy-v<version>` tag and `@drkostas/claude-human-client` on a `client-v<version>` tag. The workflow attaches the package's `npm pack` tarball to a GitHub release of the tag, which installs by URL. When the repository variable `NPM_PUBLISH` is `true` it also publishes the same tarball to npm with npm's trusted publishing, so no npm token is kept anywhere and the release carries provenance.

## 0.4.0

- `claude_human.tasks`, a task engine for the steps only a person can do. `TaskEngine.request` keeps one open task per capability and subject (a second request joins the first and nobody is told twice), asks an `Authorizer` and records a refusal before raising `Refused`, and tells the person through any `claude_human.notify` notifier with a link to the task. `verify_pending` closes a task only when its check passes, and a check that fails, is missing or times out leaves it open.
- `CommandVerifier` runs the check as a list of arguments with no shell and a timeout. `filter_chain` and `DefaultResolver` order the handoffs (link, station window, steps) for what a reader can show and where it runs, with the steps as the floor, and `head` is the surface to render first.
- `SqliteTaskStore`, the default `TaskStore`, in one SQLite file. Open or closed is derived from append only events, and comments, withdrawals, refusals and the notifier's answer are kept in the history.
- `claude_human.tasks.server`, an HTTP server on a loopback address with a bearer token, with the routes and JSON shapes a phone app reads (`/pending`, `/task`, `/history`, `/comments`, `/done`, `/open`, `/comment`, `/withdraw`).
- `claude-human task open|list|verify|withdraw|comment|history|serve`.
- `station.auth.load_or_create_token` takes a `prefix` for the token it makes.
- The skill has a new section on asking a person to do something.

## 0.3.0

- `claude_human.notify`, a notifier for a person through an ntfy server, with the standard library only. `NtfyNotifier` publishes JSON (title, message, priority, tags, click link, picture, action buttons, Markdown) with a bearer token or basic auth and a timeout, and returns `(ok, detail)` instead of raising on a network failure. `poll` reads back what the server holds. `FileNotifier` writes each message to a JSON lines file as the floor, `FirstThatWorks` tries notifiers in order, and all of them follow the `Notifier` protocol.

## 0.2.0

- `claude_human.station`, a web server that shows one window of the Mac on a phone and sends the person's taps and keys back as clicks and key presses. It listens on 127.0.0.1 only, reads the token from the `Authorization` header only, and keeps a pinned grant to its own app's window (a window it cannot find is refused, never widened to the whole display).
