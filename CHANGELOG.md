# Changelog

## Unreleased

- `whatsapp_web`: scripts that read WhatsApp Web from a tab a program controls, and parsers for their answers. `STATE` says whether the page shows the chat list, the QR code (and whether it has loaded), the phone-number form or a link code. `LINK_BY_NUMBER` and `fill_number_js(number)` take the page to its 8-character link code, which the person types into WhatsApp on their own phone. `CHATS`, `open_chat_js(title)` and `MESSAGES` read the chat list and the open chat's loaded messages, and `parse_messages` turns them into rows with WhatsApp's message id, the chat's id, who sent each one and its time from the line WhatsApp puts before it (`parse_prefix`, `day_first` for the browser's date order). Nothing in it sends a message or types a code. The signed-out page and the phone-number form were measured on the live page: the link works only once the QR has loaded, and the number must carry its + and country code, since the form reads a number without one as another country's
- `@drkostas/expo-ntfy` 0.5.0: a second config plugin, `notification-relay`, adds an Android notification listener that sends each new notification of the named apps to an HTTPS endpoint as JSON (the app, the conversation, the sender, the text, and each message of a MessagingStyle notification). Only the listed packages are forwarded, each notification once, and what the endpoint does not take waits in a bounded file queue and is sent again with a backoff. `npm run compile:service` compiles it beside the ntfy service.
- `tasks.by_hand(text)`: the first sentence of a text that tells the reader to do something by hand (open a page, sign in, type, tap, plug a cable in), or None. A question, a quote and a sentence where someone else acts pass. A tool that sends a person questions or notes can refuse such a text and ask for a decision or a permission instead. `tasks.HAND_VERBS` is the default list, and `verbs=` takes another
- `wifi.forget(ssid)` and `wifi.forget_open()`: remove one saved network, or every one anyone can join, through `sudo -n networksetup`, and read the list again (`left`). `airplay.listening()` and `airplay.receiver_off()`: whether AirPlay Receiver listens on every interface, and turning it off (the setting, ControlCenter told and restarted, then a wait until ports 5000 and 7000 close). `firewall.on()` and `firewall.turn_on(keep=)`: the application firewall's state, and turning it on with each program in `keep` added and unblocked, then read back
- `unattended` and `claude-human unattended`: whether a Mac comes back to the desktop by itself after a restart. `filevault_on()` reads `fdesetup status`, `autologin_user()` the login window's settings and `password_stored()` the presence of the automatic login password file; `read()` gives all three with the verdict `unattended`, None while any part is unknown. A Mac that an agent reaches remotely needs FileVault off and automatic login set to come back from a crash with nobody at it, and both take the person's password to change, so this only reads them
- `session_lock`: a dead holder's running CLI call is matched by either reading of its start time. `ps -o lstart` prints a local time, and in the hour the clocks repeat on the night they go back, `mktime` read it an hour off for a process started in the other half, so the call looked like another process and the next act did not wait for it
- `process.listening(sudo=False)`: every listening TCP socket with its process and address, None when lsof cannot run (only the user's own processes without `sudo`). `wifi.known_networks()`: the Mac's saved Wi-Fi networks and how each is secured, with the ones anyone can join marked `open` (Open, OWE), read through `sudo -n`
- `desktops.spaces()` reads a locked screen: yabai answers the all-desktops query with a cut-off list then, so the desktops are asked one display at a time (`query --spaces --display N`), which still answers in full. When that fails too, the first error is raised as before
- `brave.restart()`: restart a browser that stopped answering, with its windows and tabs. It is asked to quit (SIGTERM saves the session), stopped after `quit_wait` when it does not, set to continue where it left off and opened with `--restore-last-session`, and counts as restarted once it answers a tab listing. `brave.continue_where_left_off(root)` is that profile step on its own: "continue where you left off" on and the last exit marked normal, so the browser does not ask "Restore pages?" after an unclean exit
- `@drkostas/expo-adb-keeper` 0.1.0 (in `adb-keeper/`): an Expo config plugin that turns an Android phone's wireless debugging back on after a restart, after an update of the app, and every 15 minutes on Wi-Fi, when USB debugging is on, wireless debugging is off and nothing listens on the `adb tcpip` port. A machine that reaches the phone over a VPN can then find the wireless-debugging port and run `adb tcpip` again. It needs `WRITE_SECURE_SETTINGS`, granted once over adb, never presses Android's prompt on a network the phone does not trust, and asks at most once an hour on one network
- `consent` and `claude-human consent [list|allow|deny]`: the macOS consent prompts on screen ("X wants access to control Y", owned by UserNotificationCenter), a picture and the words of one (Vision OCR), and the answer a person chose pressed through the virtual keyboard (Return for Allow, Space for Don't Allow), with the prompt brought forward first and observed to close. Until such a prompt is answered every Apple Event from that program to that app hangs without an error
- `brave.has_login(site)` and `claude-human brave has-login SITE`: whether the browser's saved logins hold an entry for a site, in any profile, read from the address column of a copy of each login store (True, False, or None when none could be read). No password is read
- `android.tap(serial, package, x, y)` and `claude-human android tap`: tap an Android app over adb only once its own window has focus (`mCurrentFocus`), bringing it forward with `am start -n` and refusing on a locked phone; optionally a screenshot after
- `screenshot.keep_front` takes `activate_app`, for a caller that brings apps back its own way
- `brave.new_window` and `brave.yabai_ids` take `env` and run every command with it, like every other function here that starts a process
- One window at a time. `desktops.move_window`, `close_window` and `frame_window` each read their effect back and answer `(outcome, why)` with yabai's own words on a failure, `space_of_window` and `all_windows` (which keeps each window's frame and pid) read where a window is, and `fill_frame`/`fills` give the frame that fills the usable part of the window's screen; `frame_window(..., fallback=...)` sizes a window yabai has lost through the app's own scripting. `brave.tabs` (`[]` when the browser is not running, `None` when it did not answer), `close_tab` (read back), `active_tab`, `front_window`, `bring_forward` (the window outside links open in), `window_origin`, `window_name`, and `match_by_origin`/`join_by_origin`, which pair a browser's window ids with yabai's by corner, then name, then elimination, never by guessing. `screenshot.keep_front` hands the person back the app they were in when automation brought another app forward
- `serving`: a local HTTP server that finishes the requests it is answering before it stops. `DrainingMixin` counts the requests in progress (from the moment each is accepted), and `serve_until_stopped(server, drain_s=10)` turns SIGTERM or Ctrl-C into a drain: the server stops accepting, the open requests get up to `drain_s` seconds, then it closes. Python's default SIGTERM ended the process at once and every request on a daemon thread died with it, so a planned restart broke the calls in flight. The station and the task server use it. `retry_refused(call)` repeats a call whose connection was refused (it never reached a server, so any method is safe) and never one that got in
- `focus`: Do Not Disturb while an agent drives a window, and the person's own Focus kept. macOS gives a script no focus command, so the one path is two Shortcuts `Set Focus` actions run by name through the `shortcuts` CLI; until they exist `begin` answers ok False with what to make, never a silent pass. Every change is observed from the Focus daemon's own assertion store, `begin` hands back what was running for `restore`, and a Focus the person had running is never cancelled
- `desktops`: Mission Control desktops and the windows on them, asked of yabai, for questions CGWindowList cannot answer (it sees only the visible desktop). Every command verifies its effect by asking again, because yabai exits 0 having done nothing more than once; labels, never indices, leave the module as identifiers, with a space's uuid as the identity that survives a renumbering and a yabai restart (`relabel`, `label_for`); an empty or truncated query answer raises as an unreadable machine (often a locked screen) instead of reading as an empty one
- `retire` retires a macOS app so that nothing starts it again, and undoes that retire step by step. Each step (`disable_service`, `unload_service`, `disable_extension`, `quit_processes`, `hold_app`) does one thing, reads it back and returns a JSON record with its undo. `retire()` runs them all, and one failed step never stops the rest. `undo()` brings the app back first and enables every service before it loads any, because launchd refuses to load a disabled service. A step that was already done before the retire is left as it was unless the caller says an earlier retire of its own did it. The app is renamed into a dated hold folder on the same disk, never copied and never deleted. Processes are quit by signal, never by AppleScript, and system domain commands run through `sudo -n`. Every command goes through a `Host`, so tests use a stand-in launchctl and process list
- `session_lock` keeps a password manager CLI to one session at a time across processes (Bitwarden's `bw` keeps one session per account, so a second `bw unlock` ends the first). `SessionLock` is an exclusive flock on a state file that names its holder (pid, act, program, since when), serves waiters in the order they came, refuses a second take in the same thread, and lets go when its process dies. `run()` refuses a call when the lock file was removed and names the running call in the lock, so the next holder ends a call that a killed holder left behind. `bw_session()` unlocks `bw` with the password through a pipe, sets `BW_NOINTERACTION`, and runs `bw lock` and releases the lock on every way out
- `process`: whether a process lives (`process_alive`, None when it cannot be told, True for another user's process), the process at the other end of a local TCP connection (`peer_pid`), a process's parents from a process table (`ancestors`), and a process's memory footprint in about a microsecond (`footprint_gb`, `total_gb`: phys_footprint from proc_pid_rusage, the figure `top` shows as memory, where `top` takes about 0.65 s)
- `brave` and `claude-human brave URL JS_FILE`: run JavaScript on a page in the person's own signed-in browser (Brave by default, any Chromium browser AppleScript can drive with `--app`), in a window of its own that is closed afterwards. `--keep-open` leaves the window for a step the person finishes and prints `WINDOW <id>` (and `YABAI <id>` when yabai is installed, taken when the window is made, so it can be moved at once). With a `--key` (by default the tmux session it runs in) a caller's next `--keep-open` run reuses its window while the browser has it, so a flow of several steps keeps one window. `brave.list_tabs` asks each window for its tab ids, addresses and titles in three calls: about a minute for a thousand tabs asked one by one, under a second this way
- `@drkostas/expo-ntfy` 0.4.0: `keyTagPrefix` names a notification by a tag (`key:<name>` with the prefix `key:`), so a later message with the same key replaces it in the tray instead of adding a second one. `clearTag` lets a sender take one back: a message carrying that tag and a key tag removes the notification of that key and shows nothing. A request that was answered, ran out or failed no longer leaves its notification behind, beside the newer ones about the same thing. Both are off by default.
- `station.prepare`: `activate` focuses the recipe's own window by its id through yabai when the caller names it (`Preparer.run(..., window=id)`, or `--window <id>` read with `argv_window`), and activates the app only otherwise or when yabai refuses. Activating the app raises its key window, which can be another window on another desktop: a browser asked to show a page it had just opened in a new window took the person to the desktop where they last used the browser, and the page was not there
- `@drkostas/expo-ntfy` 0.2.1: `pollTopicOnce` gives up after `timeoutMs` (default 20 seconds, `POLL_TIMEOUT_MS`). It aborts the fetch through an `AbortSignal` and also stops waiting for a fetch that ignores the signal, and it then rejects without announcing anything or moving the mark. Before, a topic that never answered kept the background task pending, and Android's WorkManager starts no other run of a task while one is pending, so one hung connection stopped every later background poll.
- `screenshot.activate` no longer brings Finder back with `open -b`. To a running app that is a reopen, and Finder answers a reopen with no window open by opening a new window at its default folder on the visible desktop, so giving focus back after another app took it (Finder is in front when the desktop itself has focus) made Finder windows appear. Such apps are listed in `screenshot.NO_REOPEN`, and `activate` returns False for them without asking
- CI compiles the Android service the expo-ntfy plugin writes (`npm run compile:service` in js/), against the Android 36 platform and the libraries the plugin adds, so a service that does not compile fails a pull request instead of an app's build.
- `screenshot.capture_approvals()` and `capture_approval_of()`: when macOS last asked each app to confirm that it may keep recording the screen, and when it asks again (macOS 15 and later ask monthly for an app that records without the system picker). Read only, from the system's own file, with the dates in UTC.
- The station's refusal while a system dialog is up carries the dialog's app as `blocker`, and `QuartzInput(blocked_detail=...)` may be a function of that name, so the text can say which question is waiting.
- `@drkostas/expo-ntfy` 0.2.0: a message's `view` actions become buttons on the notification, up to three, each opening its link in the app like a tap (and only a link that starts with `linkPrefix`). The priority picks one of three channels. At `alarmPriority` (default 5) the message plays the phone's alarm sound as an alarm and comes through Do Not Disturb where Android allows it. At `chimePriority` (default 4) it chimes on the channel messages were always posted on. Below that it makes no sound. A message published with ntfy's default priority (3) is now silent, so set `chimePriority: 3` to keep its sound. A notification folds to its title and the first line of the message, and pulls down to the whole message. `subTextTagPrefix` shows a tag's value next to the app's name. The manifest asks for `ACCESS_NOTIFICATION_POLICY`, so the person can give the app Do Not Disturb access.
- `@drkostas/expo-ntfy` 0.2.0 also carries the fix written down for 0.1.2, which was never published. Tapping a notification that carries a link now opens that link. The service built the tap from the app's launch intent with the link attached, and the launch intent carries `CATEGORY_LAUNCHER`, so when the app was already running Android only brought its task to the front and dropped the link: the tap opened the app on whatever screen it was last on. A link now opens as a `VIEW` intent aimed at the app's package (new task, single top), which a running app receives as a new intent. A notification without a link still opens the app. The service can also be started from outside without opening the app, with a `<package>.START_LISTENER` broadcast to the receiver (`adb shell am broadcast -n <package>/.BootReceiver -a <package>.START_LISTENER`), for a phone that did not restart it after an update.
- `screenshot.screen_locked()` and `unlock.is_locked()` return `None` when the lock state cannot be read. A process outside the login session (a launchd daemon, the system domain) gets no session dictionary, and both functions used to read that as unlocked while the screen was locked. A caller that only tests truthiness behaves as before. `is_locked` now uses the same reader as `screen_locked`.
- The two npm packages are released from GitHub Actions, `@drkostas/expo-ntfy` on an `expo-ntfy-v<version>` tag and `@drkostas/claude-human-client` on a `client-v<version>` tag. The workflow attaches the package's `npm pack` tarball to a GitHub release of the tag, which installs by URL. When the repository variable `NPM_PUBLISH` is `true` it also publishes the same tarball to npm with npm's trusted publishing, so no npm token is kept anywhere and the release carries provenance.

## 0.6.0

- Security: without sckshot, capturing one window cropped the whole display to the window's rectangle, so whatever covered the window came through instead of it, and the station streamed that to a grant pinned to one app or one window. The capture now refuses a window that another application's window lies in front of and overlaps, checked before and after the grab, and returns nothing, as it already did for a window it cannot find. System chrome that draws no other application's content (the Dock, the menu bar) and windows with almost no opacity do not count, and Notification Center's banners do. Reported by Dennis. The sckshot path captures the window itself and was not affected.
- `claude-human python-app` builds a signed `.app` that runs Python, so a long-running Python program keeps its Screen Recording and Accessibility grants across Python upgrades (Homebrew signs Python.app ad hoc, and a grant given to it is lost at every upgrade)
- `screenshot.window_ids()`, the id of every window on every desktop, and `screenshot.activate(bundle_id)`, which brings an app to the front with `open -b` and needs no Automation grant

## 0.5.0

- Every function that starts a process takes an optional `env` for it: `unlock`, `relock`, `use_password`, `approve`, `screenshot.capture` and `save`, `yabai_windows`, and the classes `CommandVerifier`, `DefaultResolver` and `station.prepare.Preparer`. `None` keeps the inherited environment. With an env, the preparer also looks for yabai on that env's PATH
- `@drkostas/expo-ntfy` 0.1.1: the listener is a `specialUse` foreground service instead of `dataSync`. Android 15 stops a `dataSync` service after 6 hours in any 24 and refuses to restart it until the app is opened, so notifications stopped every afternoon. The plugin also rewrites an existing service entry and drops the old permission, so a build without `--clean` is fixed too.
- `@drkostas/claude-human-client` 0.1.0 in `client/`, a typed TypeScript client for `claude-human task serve`. It has a call for each route (`pending`, `task`, `open`, `done`, `comment`, `withdraw`, `history`, `comments`, `health`), the types of their JSON, `TaskApiError` for a status other than 2xx, retries for GETs only, and the helpers `waitingLabel`, `floorSteps` and `touchpointQuery`. The base URL and the token are passed in, and the token can be a function read at each request. Its tests run against a fake `fetch` and against the real server started on a free loopback port.
- `examples/expo-tasks`, an Expo app built on the client and `@drkostas/expo-ntfy`, with a list of waiting tasks, a task page and the history.
- CI typechecks and tests the client and the example app.
- The skill has a section on reading tasks from an app.

## 0.4.0

- `claude_human.tasks`, a task engine for the steps only a person can do. `TaskEngine.request` keeps one open task per capability and subject (a second request joins the first and nobody is told twice), asks an `Authorizer` and records a refusal before raising `Refused`, and tells the person through any `claude_human.notify` notifier with a link to the task. `verify_pending` closes a task only when its check passes, and a check that fails, is missing or times out leaves it open.
- `CommandVerifier` runs the check as a list of arguments with no shell and a timeout. `filter_chain` and `DefaultResolver` order the handoffs (link, station window, steps) for what a reader can show and where it runs, with the steps as the floor, and `head` is the surface to render first.
- `SqliteTaskStore`, the default `TaskStore`, in one SQLite file. Open or closed is derived from append only events, and comments, withdrawals, refusals and the notifier's answer are kept in the history.
- `claude_human.tasks.server`, an HTTP server on a loopback address with a bearer token, with the routes and JSON shapes a phone app reads (`/pending`, `/task`, `/history`, `/comments`, `/done`, `/open`, `/comment`, `/withdraw`).
- `claude-human task open|list|verify|withdraw|comment|history|serve`.
- `station.auth.load_or_create_token` takes a `prefix` for the token it makes.
- The skill has a new section on asking a person to do something.

## 0.3.0

- `claude_human.notify`, a notifier for a person through an ntfy server, with the standard library only. `NtfyNotifier` publishes JSON (title, message, priority, tags, click link, picture, action buttons, Markdown) with a bearer token or basic auth and a timeout, and returns `(ok, detail)` instead of raising on a network failure. `poll` reads back what the server holds. `FileNotifier` writes each message to a JSON lines file as the floor, `FirstThatWorks` tries notifiers in order, and all of them follow the `Notifier` protocol.
- A message whose link, picture or button URL is on a loopback address is refused, because the phone would open itself. `CLAUDE_HUMAN_NOTIFY_HOLD` stops every send, for test runs. `since` values in days are turned into hours for ntfy.
- `watch_sender`, which lets `claude_ops.watch.run_source` tell a person instead of a chat.
- `claude-human notify`, which reads the token or password from the environment only.
- The skill has new sections on sending notifications and on writing a watcher that tells a person or wakes a chat.

## 0.2.0

- `claude_human.station`, a web server that shows one window of the Mac on a phone and sends the person's taps and keys back as clicks and key presses. It listens on 127.0.0.1 only, reads the token from the `Authorization` header only, and keeps a pinned grant to its own app's window (a window it cannot find is refused, never widened to the whole display).
- `StationAuth`, the interface a caller implements to decide who may use the station (`check`, `app_for`) and to record what happens (`perform`, `on_input`). `TokenAuth` is the default, one shared token from the environment or a file made with mode 0600.
- `claude_human.station.prepare`, the recipe runner that puts a window into the state a task needs (`open`, `wait`, `search`, `type`, `key`, `click`, `scroll`, `activate`) in a placement phase and an input phase.
- `claude-human station` and `claude-human prepare` commands.
